\section{RewardLens Audit Construction}
\label{sec:rewardlens_audit}

RewardLens-CLEVR uses CLEVR-style procedural rendering
\citep{johnson2017clevr} to instantiate the contracts in
Sec.~\ref{sec:problem_formulation}. Only the image changes within a triplet;
the question, responses, candidate order, camera, lighting, and render seed are
held fixed.

\paragraph{Factor-specific scene contracts.}
\label{sec:factor_interventions}

Both branches perform the same class of low-level operation; their difference
is whether that operation changes the fact queried by the fixed preference
problem.

\paragraph{Count.} Both branches add a geometrically matched object at the
same intervention slot. The relevant branch adds an object in the queried
color category, whereas the irrelevant branch adds a non-target-color object.

\paragraph{Attribute.} Both branches apply the same color transition. The
relevant branch modifies the unique queried object; the irrelevant branch
modifies a matched non-target object.

\paragraph{Presence.} Both branches remove one object. The relevant branch
removes the queried color--shape conjunction, whereas the irrelevant branch
removes a matched non-target.

\paragraph{Spatial.} Both branches apply the same world-space translation.
The relevant branch moves the queried referent; the irrelevant branch moves a
matched distractor.

\paragraph{Why match branches?} The comparison is not an edit-versus-no-edit
test. Each branch applies a matched low-level scene operation while differing
in decision relevance. Relevance is defined by the deterministic gold-label
contract, not by a pixel-distance threshold.

\paragraph{Post-render validation and scope.}
\label{sec:matching_validation}

Factor-specific validators inspect realized scene state rather than trusting
requested edits: they recount target-color objects, verify target uniqueness
and color, recount the queried color--shape conjunction, or recompute the
left/right relation and displacement. Every retained triplet also satisfies
$y_R\neq y_B$ and $y_I=y_B$. These deterministic construction and post-render
checks validate the scene contracts. Pixel change is not used to define
relevance. Detailed
contracts, receipts, and edit diagnostics appear in
Appendix~\ref{app:clevr-generation-validation}.
